# SCA Analyze: OSV-Scanner vs Grype

Воспроизводимый учебный бенчмарк для сравнения двух **SCA**-сканеров на 30 сторонних GitHub-проектах. Проверяются уязвимости в зависимостях; SAST, секреты и безопасность собственного кода здесь **не** оцениваются.

## Организация

- `projects/manifest.json` — 30 проектов и закреплённые SHA (не сканируем плавающий `main`).
- `.github/workflows/scan.yml` — 30 параллельных job, сохраняющих папки `application/<project>/{osv,grype,default}`.
- `ground-truth/expected-vulnerabilities.csv` — независимо проверенный эталон; для оценки учитываются только `status=verified`.
- `scripts/build_sca_table.py` — CSV и Markdown четырёх аналитических таблиц.
- `scripts/collect_candidates.py` — **кандидаты на проверку**, а не эталон: отчёты сканеров только подсказывают, что проверять вручную.
- `tests/test_build_sca_table.py` — тесты алиасов, ошибок запуска и агрегирования.

## Как запустить

1. В GitHub откройте **Actions → SCA benchmark (OSV-Scanner vs Grype) → Run workflow** и выберите нужную ветку.
2. После выполнения скачайте артефакт `sca-benchmark-comparison`. В нём четыре таблицы в двух форматах (CSV и Markdown), `evidence-index.json` и `ground-truth-candidates.csv`.
3. Отдельные артефакты `scan-Pxxx-*` содержат фактический результат каждого инструмента (или файлы статуса сбоя) плюс `default/reference.json` с верифицированными эталонными пунктами.

### Таблицы

1. `01-reference-comparison.*`: по каждой **проверенной** уязвимости — точность совпадения каждого инструмента и примечания.
2. `02-project-summary.*`: покрытие, количество уникальных находок, расхождения и ошибки по всем 30 проектам.
3. `03-scanner-differences.*`: уязвимости «оба / только OSV / только Grype». Это **не список ложноположительных результатов**.
4. `04-benchmark-metrics.*`: сводные показатели и объём проверенного эталона.

Файл `sca-comparison.*` остаётся совместимым псевдонимом первой таблицы.

## Что такое эталон

Строка `verified` разрешена только после двух независимых проверок:

1. Конкретный `package@version` установлен в зафиксированной ревизии проекта: lockfile, manifests либо воспроизводимая разрешённая dependency tree с подтверждением.
2. Указанный CVE/GHSA/OSV advisory действительно затрагивает **эту версию** по официальным данным об уязвимости.

Затем фиксируются ссылка на файл, advisory, тип зависимости (runtime/dev/test), если известно, и оговорки. Совпадение OSV и Grype само по себе **не** подтверждает эталон. Пустой эталон означает «ещё не изучено», а не «уязвимостей нет»; отдельная найденная уязвимость не обязательно эксплуатируема в приложении.

Текущая поставка включает вручную подтверждённые примеры `P001`–`P004`; оставшиеся проекты необходимо независимо проверить на основе файла `ground-truth-candidates.csv` после следующего запуска. Нельзя честно заявлять recall/precision для всего корпуса до завершения этой проверки. Даже «только OSV» не означает, что Grype ошибся: инструменты могут разрешать разные зависимости, группировать алиасы по-разному или пользоваться разными источниками.

## Обработка ошибок и воспроизводимость

- OSV-Scanner `v2.7.0` и Grype `v0.121.2` закреплены; отчёты содержат версии инструментов и SHA исходного проекта.
- OSV Go call analysis отключён для чистого SCA и для предотвращения сбоя `govulncheck` на Grafana.
- OSV код 1 означает обнаруженные уязвимости и **не является** ошибкой сканирования. Grype код 0 означает успешную обработку (если не задан `--fail-on`).
- Неуспешное сканирование или повреждённый JSON помечаются `failed`, `not_run` или `invalid_report`, а **не** «не найдено». Скрипт не подделывает пустой JSON.
- Сборка `compare` работает даже при сбое отдельных job и отображает пропуски из манифеста.
- Базы данных меняются со временем: для строго идентичных результатов потребуются также снимки/даты баз OSV/Grype, а не только версии бинарников.

Локальные тесты: `python -m unittest discover -s tests -v`.
