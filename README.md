# SCA Analyze: OSV-Scanner vs Grype

Воспроизводимый учебный бенчмарк для сравнения двух **SCA**-сканеров на 30 сторонних GitHub-проектах. Проверяются уязвимости в зависимостях; SAST, секреты и безопасность собственного кода здесь **не** оцениваются.

## Главный результат: 30 каталогов в GitHub

Откройте **[`application/`](application/)**: внутри **30 папок приложений**.
В каждой находятся три папки:

- `osv/` — исходный `result.json` OSV-Scanner и нормализованный `findings.json`;
- `grype/` — исходный `result.json` Grype и нормализованный `findings.json`;
- `default/` — объединённый список найденных обоими инструментами уязвимостей (`reference.json` + `reference.csv`).

В [`application/INDEX.csv`](application/INDEX.csv) перечислены **все 30 приложений** и количества находок каждого инструмента; [`application/README.md`](application/README.md) описывает методику и ограничения. Данные получены из [успешного запуска GitHub Actions](https://github.com/maksimrin8-design/sca-analyze/actions/runs/42363667019).

**Методологически важно:** `default` — составной предварительный эталон из объединения находок двух инструментов. Это не независимый полный ground truth. Он не позволяет объективно рассчитать precision/recall OSV и Grype без независимой проверки, и пропуски обоих инструментов могут в нём отсутствовать. Поле `reference_status` различает ранее подтверждённые примеры и записи, полученные только из сканеров.

Публикация каталогов воспроизводима: [`scripts/publish_sca_folders.py`](scripts/publish_sca_folders.py) и [workflow публикации](.github/workflows/publish-sca-evidence.yml).

## Организация

- `projects/manifest.json` — 30 проектов и закреплённые SHA (не сканируем плавающий `main`).
- `.github/workflows/scan.yml` — 30 параллельных job, сохраняющих папки `application/<project>/{osv,grype,default}`.
- `ground-truth/expected-vulnerabilities.csv` — независимо проверенный эталон; для оценки учитываются только `status=verified`.
- `scripts/build_full_sca_table.py` — одну полную таблицу наблюдаемых уязвимостей SCA в CSV и Markdown; `scripts/build_sca_table.py` сохранён для исторической проверки только по подтверждённому эталону.
- `scripts/collect_candidates.py` — **кандидаты на проверку**, а не эталон: отчёты сканеров только подсказывают, что проверять вручную.
- `tests/test_build_sca_table.py`, `tests/test_full_sca_table.py` — тесты алиасов, ошибок запуска, объединения результатов двух сканеров и полного отчёта.

## Как запустить

1. В GitHub откройте **Actions → SCA benchmark (OSV-Scanner vs Grype) → Run workflow** и выберите нужную ветку.
2. После выполнения скачайте артефакт `sca-benchmark-comparison`. В нём одна сравнительная таблица SCA в двух форматах (CSV и Markdown), `evidence-index.json` и `ground-truth-candidates.csv`.
3. Отдельные артефакты `scan-Pxxx-*` содержат фактический результат каждого инструмента (или файлы статуса сбоя) плюс `default/reference.json` с верифицированными эталонными пунктами.

### Единственная итоговая таблица — SCA

- `sca-comparison.csv` и `sca-comparison.md` — два формата **одной таблицы**. Столбцы: проект, эталонная уязвимость, OSV-Scanner, Grype, с комментариями для полного, частичного или отсутствующего совпадения.
- Каждый из 30 проектов будет в таблице. Для каждой наблюдаемой связки «пакет + установленная версия + уязвимость» будет отдельная строка: найдено OSV, найдено Grype, оба или ни один (если известна подтверждённая эталонная запись). Для проектов без обнаруженных находок добавляется поясняющая строка. CVE/GHSA-алиасы и повторные записи по одному компоненту объединяются.
- `evidence-index.json` — вспомогательная техническая диагностика; `ground-truth-candidates.csv` — рабочий список гипотез для ручной проверки, **не вторая итоговая таблица**.
- SAST, Secret Scanning и SBOM относятся к другим направлениям практики и в этом бенчмарке не анализируются.

## Что такое эталон

Строка `verified` разрешена только после двух независимых проверок:

1. Конкретный `package@version` установлен в зафиксированной ревизии проекта: lockfile, manifests либо воспроизводимая разрешённая dependency tree с подтверждением.
2. Указанный CVE/GHSA/OSV advisory действительно затрагивает **эту версию** по официальным данным об уязвимости.

Затем фиксируются ссылка на файл, advisory, тип зависимости (runtime/dev/test), если известно, и оговорки. Совпадение OSV и Grype само по себе **не** подтверждает эталон. Пустой эталон означает «ещё не изучено», а не «уязвимостей нет»; отдельная найденная уязвимость не обязательно эксплуатируема в приложении.

Текущая поставка включает пять вручную подтверждённых эталонных записей для `P001`–`P004`. Остальные строки полной таблицы имеют статус `candidate_not_independently_verified`, так как являются объединением наблюдений OSV и Grype, **а не независимо полученным полным эталоном**. Для надёжной оценки пропусков обоих инструментов, precision и recall по всем 30 проектам требуется независимая проверка всех зависимостей и advisory (в том числе не найденных ни одним сканером). `ground-truth-candidates.csv` — лишь короткий вспомогательный рабочий список. Нельзя честно заявлять recall/precision для всего корпуса до завершения этой проверки. Даже «только OSV» не означает, что Grype ошибся: инструменты могут разрешать разные зависимости, группировать алиасы по-разному или пользоваться разными источниками.

## Обработка ошибок и воспроизводимость

- OSV-Scanner `v2.7.0` и Grype `v0.121.2` закреплены; отчёты содержат версии инструментов и SHA исходного проекта.
- OSV Go call analysis отключён для чистого SCA и для предотвращения сбоя `govulncheck` на Grafana.
- OSV код 1 означает обнаруженные уязвимости и **не является** ошибкой сканирования. Grype код 0 означает успешную обработку (если не задан `--fail-on`).
- Неуспешное сканирование или повреждённый JSON помечаются `failed`, `not_run` или `invalid_report`, а **не** «не найдено». Скрипт не подделывает пустой JSON.
- Сборка `compare` работает даже при сбое отдельных job и отображает пропуски из манифеста.
- Базы данных меняются со временем: для строго идентичных результатов потребуются также снимки/даты баз OSV/Grype, а не только версии бинарников.

Локальные тесты: `python -m unittest discover -s tests -v`.
